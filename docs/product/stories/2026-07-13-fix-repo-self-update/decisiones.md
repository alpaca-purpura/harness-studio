# Decisiones — fix: repo configurable para self-update

> Una entrada por decisión conversada. Estado: PROPUESTA → FIRMADA.
> Origen: el operador reporta que una instalación empaquetada (Tauri/.deb) nunca puede
> usar el botón «Actualizar» — el sidecar arranca el daemon sin `--repo`/`ARNESIA_REPO`
> y no hay forma de fijarlo salvo relanzar el binario a mano por CLI.

| # | Fecha | Decisión | Porqué | Estado |
|---|-------|----------|--------|--------|
| 1 | 2026-07-13 | **Alcance = bugfix, no feature nueva.** Se permite CONFIGURAR el repo desde Ajustes cuando el daemon arrancó sin flag/env; no se toca el mecanismo de update en sí (sigue siendo build local, RF-104..107 intactos). Releases remotos (KIT-06) siguen fuera de alcance. | El hueco es real (confirmado por investigación de código) pero acotado: falta UN puente entre «el daemon ya sabe pedir un repo» y «el usuario instalado puede dárselo». | **FIRMADA** (operador, 2026-07-13) |
| 2 | 2026-07-13 | **Mecanismo = separar CONFIGURAR de DISPARAR.** Nuevo endpoint `PUT /api/self-update/repo` (acepta `{path}`, valida, fija y persiste) — DISTINTO de `POST /api/self-update` (RF-104), que sigue ignorando el body por completo. Persistencia nueva `~/.arnesia/self-update.json`. Precedencia al boot: `--repo`/`ARNESIA_REPO` (si viene) > persistido > vacío (estado `sinRepo` de siempre). | Aísla el cambio: el endpoint que EJECUTA código (build+swap+re-exec) no gana superficie nueva; solo gana superficie el que fija un dato, y ese dato se valida antes de aceptarse. | **FIRMADA** (operador, 2026-07-13) |
| 3 | 2026-07-13 | **UI = selector de carpeta NATIVO Tauri** (`@tauri-apps/plugin-dialog`), no `<input type=text>`. Gesto real de OS: no scriptable por contenido web/XSS de la SPA (un input+submit sí lo sería). En un browser plano (sin Tauri, dev) el flujo de configuración queda OCULTO — se mantiene el mensaje actual apuntando a `--repo`/`ARNESIA_REPO`. | El texto libre reabriría parcialmente el riesgo que motivó RF-106 (path atacante-controlado); el picker nativo exige una acción humana que un script de página no puede simular. | **FIRMADA** (operador, 2026-07-13) |
| 4 | 2026-07-13 | **Re-alcance de RF-103/RF-106 (decisión #4 del paquete boton-actualizar, FIRMADA 2026-07-07): «la ruta del repo se configura AL DAEMON, jamás desde la UI/request» se acota específicamente al request que DISPARA el update** (`POST /api/self-update`, que sigue e ignorando el body — CERO cambio ahí). Configurar el repo es una acción SEPARADA, auth-gated igual que el resto de `/api/*`, validada server-side con las mismas reglas de `Verificar` antes de aceptar/persistir, y solo alcanzable vía gesto nativo de OS. No es la superficie que RF-106 cerraba. | Sin esta aclaración el fix contradice una decisión firmada; el espíritu de RF-106 (el disparador no ejecuta código de un path arbitrario del request) queda intacto — se abre una vía de configuración deliberada, no la de ejecución. | **FIRMADA** (operador, 2026-07-13) |
| 5 | 2026-07-13 | **Validación server-side reutiliza las reglas de `Verificar`** (repo existe · `go.mod` es el módulo esperado · `scripts/bundle.sh` presente · `go`/`pnpm`/`bash` en PATH) ANTES de fijar/persistir un path — rechazo inmediato con detalle, nunca aceptación ciega de un path que luego falla en silencio. | Consistencia: un path que no pasaría el paso ① del self-update tampoco debería poder guardarse como «el repo configurado». | **FIRMADA** (operador, 2026-07-13) |
