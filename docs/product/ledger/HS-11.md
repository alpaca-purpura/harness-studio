*Cierre «run async + gate post-run» (2026-07-23):* diseño ya decidido con el operador el mismo
día (202+run-id, `GET .../runs/{id}`, gate reusa CAP-70/71) construido completo. Investigación
previa cazó un bug real independiente del async: `BoxConductor.RunWith.awaitResult` descartaba
`EventControlRequest` en silencio — cualquier rol con permiso de escritura habría colgado el
subproceso para siempre (`--permission-prompt-tool stdio` rutea TODO write tool ahí sin
excepción, `escrituraDirecta` en `claudecode/conductor.go`; nadie respondía el
`control_response`). Ambos resueltos en el mismo cierre:

- **Bug de seguridad:** `awaitResult` ahora auto-resuelve todo `control_request` contra el
  `PermissionSet` del rol (Allow→allow · Deny/Ask→deny) — un run T3 es headless por diseño
  (`agencia-dentro-del-frame`, `orquestacion-determinista-entre-cajas`), no hay humano en el
  loop para el click de `permisos-gui`; Ask sin humano a quien preguntarle se deniega, nunca
  cuelga en silencio ni auto-aprueba de más.
- **Async:** `RunBox` (síncrono) → `StartRun` (valida síncrono — 404/422/409 le siguen llegando
  al caller en el POST mismo — y devuelve `202`+run_id) + `runAsync` (goroutine, ctx propio vía
  `context.WithoutCancel`) + `GetRun` (registro in-memory `map[runID]*RunStatus`, mutex). Nuevo
  endpoint `GET /api/harnesses/{id}/boxes/{boxId}/runs/{runId}`. `event: run` sigue viajando por
  `/events` sin cambio de contrato (started/finished/error).
- **Gate post-run:** reusa `ports.ConformancePort` (el MISMO puerto de `GET .../conformance`,
  cableado en `main.go` antes de `NewRunService` ahora) — corre `RunGraph` SOLO si el run
  auto-permitió ≥1 escritura (`BoxOutcome.EscribioAlgo`), adjunta el veredicto a
  `RunResult.Conformance`. Mismo patrón que CAP-71 (chat corre conformance tras un turno con
  escrituras), disparado del lado backend porque un run headless no tiene turno de FE del que
  colgarse.

Tests nuevos: `TestConductorAutoResuelveControlRequest` (3 casos: allow/ask-denegado/deny
explícito) + `TestRunAsyncDevuelveRunIDInmediato` + `TestRunAsyncValidacionSigueSincrona` +
`TestRunAsyncGatePostRunSoloSiEscribio` (2 casos) — todos con fakes, sin subproceso real,
