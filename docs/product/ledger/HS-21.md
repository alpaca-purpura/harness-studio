### HS-21 · Cablear `estado.sh` a CI: cifras stale rompen el merge — `decidida` · `vig:vigente`

*Cruda (operador, 2026-07-09):* «arranca y arregla todo con mucho cuidado, investigando antes,
poniendo tus propios métodos de validación y verificación de que lo hiciste bien y al final
auditas. Trata de usar subagentes para no llenar el contexto.» Eje elegido: **N2 (endurecer
honestidad)**; este = **Paquete A** (el quick-win de mayor palanca).

*Problema:* `scripts/estado.sh` GENERABA el bloque `<!--stats-->` del checkpoint desde el estado
real (RF-178/HS-20), pero **nadie lo corría en CI/hook** → drift silencioso: alguien cambia código,
las cifras del checkpoint quedan stale, nada lo caza. La disciplina «cifras se generan» (§4)
dependía de que un humano se acordara de correr el script.

*Investigación (subagente, evidencia real):* `estado.sh` escribe SOLO `checkpoint.md` (solo el
bloque), es **determinista/idempotente** (md5 ×3), sin red/sidecar (solo `go run`), python3 stdlib
(0 pip), ~22 s (3× `go run`). **Gotcha confirmado:** `STAMP=git log -1 HEAD date` inyectado como
`medido {stamp}` → un commit de otro día sin cambio de cifras rompería un `git diff` ingenuo (falso
positivo). Alcance R2 = `{cmd,internal,web/src,src-tauri/src}×{go,ts,tsx,rs}` → `scripts/`+`.github/`
**fuera** ⇒ no exige capability de producto.

*Decisiones firmadas (D1-D4):* **D1** la fecha se NEUTRALIZA en el check (es procedencia, no cifra;
`norm()` reduce `medido <ISO>` a `<DATE>` en ambos lados). **D2** el step vive en el job `go` (ya
tiene toolchain+cache). **D3** CI-only, sin lefthook (22 s prohibitivo pre-commit; el gate duro es
CI). **D4** modo `estado.sh --check`: regenera en memoria, compara cifras, exit 1 drift / exit 0
sync, **NO escribe** el árbol (más limpio que `regenera && git diff`, que ensucia el runner y rompe
por fecha). **D-módulo** sin capability de producto (infra/honestidad, fuera de R2).

*Implementación (5 superficies):* `scripts/estado.sh` (+`--check`, default retro-compatible) ·
`.github/workflows/ci.yml` (step `estado-drift` en job `go` tras `build`) · `conventions/ci.md`
(fila `ci-estado-drift` sev `error`) · `lefthook.yml` (`pre-commit estado-cifras`, auto-heal) ·
`conventions/git-hooks.md` (fila `lefthook-precommit-estado`). Ruleset 247→**249** (2 checks nuevos
de convención); checkpoint regenerado self-consistent.

*Validación propia (métodos):* **V1** sync→exit 0 · **V2** drift real (247→248; boundaries
17→18)→exit 1 con diff · **V3** solo-fecha→exit 0 (sin falso positivo) · **V4** `go build/vet/test`+
fitness 0 FAIL. Efecto esperado: la fila nueva de `ci.md` sumó 1 check al ruleset (**247→248**,
deferred 205→**206**, mecanismo CI); checkpoint regenerado → self-consistent.

*Auditoría adversarial (subagente):* veredicto **MERGEABLE**. 6/6 puntos ✓ (falso-negativo,
falso-positivo, CI-wiring, determinismo STAMP, retro-compat, doc-as-code). 2 hallazgos BAJA →
resueltos en el mismo turno: **(1)** `norm()` blindado a fecha ISO (evita enmascarar una cifra
futura tras «medido»); **(2)** esta ficha `ledger/HS-21.md` + item BACKLOG.

*Resolución de Δ1 (orden «resolvé la desviación antes de firmar», 2026-07-10):* el gate ya no solo
detecta — se agregó auto-regen. Camino con evidencia E2E (nada de supuestos): **`pre-push`
DESCARTADO** (lefthook 1.13.6 lo saltea con «no matching push files» en push real, hasta trunk-based
con archivos en rango; solo corre con `--force` que git no pasa) · **`stage_fixed` DESCARTADO** (no
stagea el checkpoint cuando el trigger es otro archivo) · **`pre-commit` + `git add` ELEGIDO** y
verificado con commit REAL (drift 18→17 → el commit salió con trigger + checkpoint fresco). Hook
`pre-commit estado-cifras` (glob `*.{go,ts,tsx,rs,yaml,md}`): decide con `--check`, regenera+`git add`
si driftó. Costo aceptado: ~20-50s/commit relevante. Doc en `git-hooks.md` v1.1 → ruleset 248→**249**.

*Estado:* paquete `done` — **gate PARIDAD 🧑‍⚖️ FIRMADO 2026-07-10** («firma y commitea directo a
main») tras 2 auditorías adversariales MERGEABLE. PARIDAD 10 filas + 5 desviaciones en
